# Changelog v2.3.0

## Release Date
2026-04-02

## Feature: LLM 推理细化 RW + ctx 变动 watcher

### 概述

本次更新解决了两大核心问题：

1. **`evolve` 命令导致 RW 值暴涨而非收敛**：旧版 `resolve` 拆分对象时使用 `judge_batch` 批量判断，fallback 为 `'RW'`，导致每次拆分都产生大量新的 RW 单元格
2. **ctx 变动无法观测**：没有 watcher 机制，交互式修改 ctx 后无法自动看到矩阵变化

### 问题分析

#### Bug 1: RW 暴涨

旧版 `resolve` 逻辑：

```
parent (RW=7) → 拆成 6 个 children
每个 child.add_obj() 时，所有属性初始化为 RW
judge_batch() 批量判断，若 LLM 返回不完整，fallback 到 'RW'
结果: 1 个 RW → 6 个 RW，新增 5 个 RW
```

#### Bug 2: JSON 序列化失败

`incidence_reasoning` 的 key 使用 `(oid, aid)` 元组，JSON 不支持元组作为 key，导致 `save_workspace` 时 crash。

### 解决方案

#### 1. `llm.py` — 新增 `judge_cell` 方法

```python
def judge_cell(self, obj_name, obj_desc, attr_name, attr_desc, context=''):
    """逐个判断单个 (obj,attr) 单元格，提供推理过程"""
    # 问 LLM: 模块应该 R 还是 W 这个通道？
    # 返回: {'direction': 'R'|'W'|'0'|'RW', 'reasoning': '...'}
```

#### 2. `engine.py` — 多处改动

**新增字段**：
- `DAGNode.incidence_reasoning`: 存储每个 incidence 值的推理过程
- `Engine.incidence_reasoning`: 当前工作区的推理 dict
- `Engine._batch`: 批处理标志，抑制中间过程的 watcher 触发

**新增方法**：

```python
def refine_rw_cell(self, oid, aid, pv, llm, context=''):
    """逐个调用 judge_cell 细化 RW 单元格，存储推理到 incidence_reasoning"""
    result = llm.judge_cell(on, od, an, ad, context)
    self.incidence_reasoning[(oid, aid)] = {
        'direction': direction,
        'reasoning': reasoning,
        'parent_value': pv,
        'ts': '...',
    }
    return direction
```

**resolve 修复**：
- 用 `refine_rw_cell` 替代 `judge_batch` 批量 fallback
- `pending` 元组从 4 元组 `(nid,aid,idx,pv)` 改为 3 元组 `(nid,aid,pv)`
- fallback 改为 `results.get(idx, pv)` 使用 parent 原始值，而非固定 `'RW'`

**JSON 序列化修复**：
- `save_workspace`: `incidence_reasoning` key 转字符串 `'oid|aid'`
- `load_workspace`: 读取时转回元组

**watcher 机制完善**：
- `_mark_dirty()`: 设置 dirty 并触发 watcher（batch 模式除外）
- `commit()`: 提交时触发 watcher 显示最终矩阵
- `goto_node()`: 切换节点后触发 watcher

#### 3. `cli.py` — `evolve` 命令重写

**新策略（两步走）**：

```
Step 1: refine（先尝试细化 RW）
  → 遍历每个 RW 单元格，逐个调用 judge_cell
  → 若 LLM 能明确判断为 R/W/0 → 直接更新，RW 减少
  → 打印推理过程和结论

Step 2: split（LLM 无法明确时再拆分对象）
  → 只有 judge_cell 仍返回 RW 才触发对象拆分
  → 拆分时也用 refine_rw_cell 传承推理给 children
```

**新增选项**：
```bash
konceptos evolve --all          # 完整流程（refine + split）
konceptos evolve --skip-refine  # 跳过 refine，直接拆分（用于对比）
```

**RW 演变过程**:

```
初始 RW=7 (fireboy, watergirl 各有多个 RW 单元格)
↓
Refine 阶段: judge_cell 逐个细化
  - FireBoy.game_state: RW → W
  - FireBoy.gem_list: RW → W
  - WaterGirl.gem_list: RW → W
  - WaterGirl.player_state: RW → R
  - PhysicsEngine.velocity: RW → R
  - ...
↓
Evolve split: 当 RW 无法细化时，拆分对象
  - fireboy → MovementController, ElementalAffinity, GemCollector, CharacterState
  - physics_engine → gravity_system, kinematic_integrator, impulse_handler
↓
最终: RW=0，|G|=13
```
