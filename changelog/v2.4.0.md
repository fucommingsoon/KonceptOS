# Changelog v2.4.0

## Release Date
2026-04-02

## Feature: K Artifacts 机制

### 概述

K 在 `evolve` 演变过程中，每次 G/M/I 矩阵变化都生成关联的代码产物（channel schema、module skeleton、contract bridge 等）并带上签名。K 变则签名变，产物供 `build2` 直接复用，跳过 LLM 重新生成。

### 解决的问题

1. **`build2` 每次都强制调用 LLM 生成代码**：耗时长且不稳定
2. **K 的 channel schema 没有沉淀**：无法复用类型定义
3. **Module skeleton 不存在**：生成时缺乏初始框架参考

### 数据模型

在 `DAGNode` 新增 `artifacts: dict` 字段：

```json
{
  "artifacts": {
    "channel_schema_entity_positions": {
      "sig": "sha256:abc123...",
      "type": "channel_schema",
      "code": "interface EntityPositions { fireboy: Entity; watergirl: Entity; }",
      "k_deps": ["entity_positions"],
      "ts": "2026-04-02 19:30:00"
    },
    "module_skeleton_MovementController": {
      "sig": "sha256:def456...",
      "type": "module_skeleton",
      "code": "const MovementController = { name: 'MovementController', init(){}, update(){}, render(){} };",
      "k_deps": ["MovementController", "entity_positions", "velocity_vectors"]
    }
  }
}
```

- `sig`: `hashlib.sha256(json.dumps(K_subset)).hexdigest()[:16]`
- `artifact_key`: `{type}_{target}`，如 `module_skeleton_MovementController`
- `type`: `channel_schema` | `module_skeleton` | `tiles_constants` | `contract_bridge`

### 新增 CLI 命令

```bash
python -m konceptos artifacts list       # 列出当前 K node 的所有 artifact
python -m konceptos artifacts check      # 检查哪些 artifact sig 已失效
python -m konceptos artifacts gen <key>  # 生成单个 artifact
python -m konceptos artifacts gen --all  # 生成所有 artifact
```

### 新增 Engine 方法

| 方法 | 说明 |
|------|------|
| `compute_artifact_sig(key)` | 根据 K 子集计算 artifact SHA256 签名 |
| `get_artifact(key)` | 获取 artifact（若 sig 有效则返回，否则 None） |
| `set_artifact(key, type, code, deps)` | 存储 artifact，自动计算 sig |
| `invalidate_artifacts(k_deps)` | K 变化时标记相关 artifact sig 失效 |
| `artifact_status()` | 检查所有 artifact 的 sig 有效性 |

### 新增 Codegen 生成器

| 函数 | 说明 |
|------|------|
| `generate_channel_schema_code(engine, channel_name)` | 生成 channel 的 TypeScript interface |
| `generate_module_skeleton_code(engine, module_name)` | 生成模块空壳（init/update/render 框架） |
| `generate_tiles_constants_code(engine)` | 生成 TILES 常量代码 |

### build2 集成

`build2` 命令新增 `--use-artifacts` 选项（默认开启）：

```
For each module in topo order:
  1. 检查是否有有效的 module_skeleton artifact
  2. 若有 → 将 skeleton code 作为额外 context 注入 LLM prompt
  3. 若无或 sig 失效 → 走 LLM 生成，生成后存入 artifact
  4. 最终代码也存入 module_skeleton artifact（供后续复用）
```

### 黑屏问题修复（附带）

**根因**：`framework.js` 的 `ALL_MODULES` 查找 `mod_input_handler`，但生成代码导出 `const input_handler`（无 `mod_` 前缀）。所有模块都走到空 stub → `gameInit()` 什么都没做 → 黑屏。

**修复**：
- `codegen.py generate_impl_context` 使用实际模块名（如 `const MovementController = {...}`）
- `codegen.py _build_game_loop_js` 修正查找逻辑匹配实际导出

**其他修复**：
- `build_module` prompt 改用 global variable 导出（替代 `export default`）
- `max_tokens` 从 8000 提升到 32000（防止代码截断）
